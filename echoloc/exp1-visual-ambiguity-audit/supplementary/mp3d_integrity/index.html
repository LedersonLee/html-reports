MP3D query-integrity audit

Audited the 960 Experiment-1 sampled MP3D query IDs once (the three backbones consume the same RGB/pose query). RGB filename, poses.txt row, chunks.json frame, map occupancy, and MP3D scan-hole metadata were checked.

  • RGB exists: 960/960
  • poses.txt equals corresponding chunks.json frame: 960/960
  • GT map pixel is free: 960/960
  • scan_nohit_lower > 15%: 93/960 (9.69%)
  • median / p95 scan-nohit: 0.045% / 29.61%

The MP3D README states that raw-scan RGB/depth can be black where the mesh has holes, while map.png and depth_radial_floorplan use a closed floorplan proxy. Such frames are an observation/geometry artifact, not natural visual ambiguity.
