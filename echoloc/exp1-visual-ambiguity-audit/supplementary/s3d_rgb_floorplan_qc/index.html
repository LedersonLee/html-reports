S3D RGB–floorplan geometry QC gate

Do not use the flagged views as visual-ambiguity evidence. This test compares rendered scan depth and floorplan-proxy depth at the same stored RGB/pose index. It does not identify whether the cause is a pose/map-frame convention error or a structural representation mismatch, so both possibilities remain open.

What is being compared?

  • Rendered scan depth is not a network prediction and is not produced by the floorplan model. It is Structured3D's source depth.png, paired with the same rgb_rawlight.png; it is converted from camera-forward z-depth (mm) to radial range and gravity-aligned exactly as the RGB is.
  • Floorplan-proxy depth is also not a learned prediction. It is a synthetic range image rendered from the extruded floorplan.glb: the rasterised 2D map walls, floor, and ceiling, at the stored pose/yaw. Thus it is the depth that the current 2D floorplan claims that RGB view should see.
  • This QC uses a robust horizontal profile: for each image column, the median depth over rows 170–189 (around the optical centre). Zero/no-return scan pixels are omitted.

How to read the metrics

  • Profile MAD (m) = median over valid columns of |rendered depth − floorplan-proxy depth|. It is a robust typical per-ray disagreement; 0.95 m means at least half of usable horizontal directions differ by about 0.95 m or more.
  • Profile correlation = Pearson correlation between the two 640-column profiles. Near +1 means near/far structure changes in the same directions; near 0 means no directional correspondence; below 0 means they vary in opposite directions. It measures shape agreement, not localization accuracy.
